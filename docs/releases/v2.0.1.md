# v2.0.1

Palworld Server Panel 2.0.1 是一次更新可靠性和 Docker 安全边界修复版本。重点解决 SteamCMD 因过期或损坏 manifest 反复更新失败，以及更新中断后无法自动续传的问题。

## Highlights

- SteamCMD 固定使用 TCP 模式，降低连接 Steam CM 时长时间卡住的概率。
- 单次 SteamCMD 操作增加 30 分钟超时，失败后继续按配置重试。
- 检测到 `StateFlags=6`、`UpdateResult=6` 或日志中的 `Access Denied` 时，自动备份旧 manifest 并重新获取当前版本。
- 更新过程中容器或服务器异常重启后，可根据非完整 manifest 和断点下载目录自动续传。
- 面板仍会验证目标 depot manifest，并等待游戏进程和 RCON 恢复后才将更新标记为完成。
- Docker 面板端口默认只绑定 `127.0.0.1`，避免绕过可信反向代理直接访问无登录面板。
- 修正文档中关于面板访问方式和 Docker 游戏更新行为的过时描述。

## Upgrade Notes

Docker 用户：

```bash
git pull
docker compose up -d --build
```

不要使用 `.env.example` 覆盖现有 `.env`。如需调整 SteamCMD 网络策略，可以在 `.env` 中设置：

```env
# auto、direct 或 proxy
STEAMCMD_NETWORK_MODE=auto
```

面板现在默认监听 `127.0.0.1:8080`。如果此前直接通过 `http://服务器IP:8080` 访问，请配置同机 Nginx/Caddy、SSH 隧道或可信私有网络入口。

systemd 用户可以正常升级面板代码，但本版本的 SteamCMD manifest 自动修复和中断续传主要针对 Docker Compose 后端：

```bash
git pull
sudo bash install.sh
sudo systemctl restart palworld-panel.service
```

## Recovery Behavior

自动修复只处理 SteamCMD 应用状态和对应临时下载目录：

- 旧 `appmanifest_2394010.acf` 会重命名为带 UTC 时间戳的 `.stale-*` 备份。
- 只清理应用 `2394010` 的 `steamapps/downloading` 和 `steamapps/temp` 临时目录。
- 不删除 `Pal/Saved`、世界存档、玩家存档或服务器配置。
- 已完成的 manifest 状态为 `StateFlags=4`，普通容器重启不会重复连接 Steam 或重新下载。
